# RimWorld 1.7 API監査（T0）

2026-10-23。対象ビルドの参照アセンブリを読み取り、仕様10の技術ゲートA00の4条件に接続先を割り当てた記録。同日、ユーザー提供の実DLLで内部の挙動も確認した（§5）。ゲーム本体のコードは転載していない。

## 1. 対象ビルドと参照

| 項目 | 固定値 | 根拠 |
|---|---|---|
| ゲーム | RimWorld 1.7.4985（Steam unstableブランチ） | NuGet `Krafs.Rimworld.Ref` 1.7.4985-unstable（2026-10-22公開、Ludeon許諾のメタデータのみの参照アセンブリ） |
| エンジン | Waylith（Unity不使用）、Ludeon版 .NET 10 | 同パッケージのREADMEとRimRef discussion #108 |
| ゲーム側TFM | `net10.0` | 同README「1.7 → net10.0」 |
| SDK | .NET SDK 10.0.402 | コンテナで実際に使用した版 |
| Harmony | コンパイル時 `Lib.Harmony.Ref` 2.3.1（netstandard2.0参照。実行時のHarmony MODが古い版でも参照版を満たすよう、入手可能な最低版に固定）、実行時はHarmony MOD（`brrainz.harmony`）に依存 | 下記4.1 |
| テスト | xUnit、`net10.0` | 計画の初期案net8.0から変更（同一SDKで揃えるため） |

ローカルにゲームがある場合は `-p:RimWorldManagedPath=<RimWorldの管理DLLフォルダ>` で実DLLを参照に切り替える。参照先は個人環境の値でありリポジトリに固定しない。ゲームDLL・参照パッケージはリポジトリ・配布ZIPに含めない。

1.7は2026-10-23時点でunstableブランチのみ。安定版公開時はビルド番号を更新し、本監査とA00～A16を再実施する。1.6は`net472`・Unityであり、本DLLは読み込めない。1.6対応は別ビルドが必要（仕様U5の拡張扱い）。

## 2. A00の4条件と接続先

| 条件 | 接続先（参照アセンブリで存在とシグネチャを確認） | 判定 |
|---|---|---|
| 資産補正 | 封印箱: ThingDefの`MarketValue`基本値を0とし、`ThingComp.GetStatOffset(StatDef)`で盗品だけ申告価値を加算（預かり箱は0のまま）。未受領残高: `WealthWatcher.ForceRecount(bool)`のHarmony Postfixで非公開フィールド`wealthItems`へ再計算ごとに一度だけ加算（`WealthItems`と`WealthTotal`のどちらで合算されても二重計上しない）。`Map.PlayerWealthForStoryteller`の入力 | 実コードで確認（§5）。Postfixの条件不備を修正 |
| サイト保存 | `MapParent`派生の独立WorldObject。`MapGeneratorDef`（virtual getter）、`ShouldRemoveMapNow(out bool)`、`Notify_MyMapAboutToBeRemoved()`、`GetOrGenerateMapUtility.GetOrGenerateMap(PlanetTile, IntVec3, WorldObjectDef, …)`、`CaravanEnterMapUtility.Enter(...)` | 設計変更あり（下記3） |
| DLC不要の配送 | `DropPodUtility.DropThingsNear(IntVec3, Map, IEnumerable<Thing>, …)`、`DropCellFinder.TradeDropSpot(Map)`、`DropCellFinder.TryFindDropSpotNear(...)`。いずれも本体（Assembly-CSharp）でDLC名前空間ではない | 実コードでDLC判定なしを確認（§5）。描画を伴う実動作はA01 |
| 保存境界 | 台帳は`WorldComponent.ExposeData`＋`Scribe_*`。副作用は効果IDで照合（T3）。保存はtick処理の外で行われる前提だが本体非公開のため未確定 | 自動保存がtick外であることを実コードで確認（§5）。実際の保存/ロードはA11 |

## 3. 設計変更: サイトマップの寿命

`MapParent.ShouldRemoveMapNow`の既定は`false`で、派生クラスが破棄条件を決める（1.7.9787の実コードで確認）。マップを残すとプレイヤー不在でも常時tickされ、仕様9「未ロードサイトのマップを常時起動しない」に反する。そこで次の方式とする（仕様7を更新）。

- 退出後のマップは破棄してよい。ただし破棄直前（`Notify_MyMapAboutToBeRemoved`）に、箱の所在（金庫内/地面/持出済）、金庫ごとの開錠進捗・破壊状態・損失判定済み、生存守備兵の残ポイント、警報・増援状態を`SiteRecord`へ書き戻す。
- 再訪時は`SiteRecord`から同じseed・同じ配置で再構築し、取得済みの箱・死亡した守備兵・破壊された金庫は戻さない。在庫・守備を無料補充しない。
- 撤収期限・警報は絶対tickで台帳側を進め、未ロード中に越えた増援は次のロードで一度だけ反映する。

仕様の禁止事項「在庫・死亡・損失状態を復元せず毎回新規マップで無料補充」には該当しない。

## 4. 補助的な接続先

### 4.1 Harmonyの必要性

最小限に限定し、次の3か所だけに使う。

1. `WealthWatcher.ForceRecount` Postfix: 未受領残高（地図上の実体がない）を資産額に加える。ThingComp方式では表現できない。
2. `CaravanFormingUtility.AllReachableColonyItems` Postfix: 自コロニー契約箱をキャラバン候補から除外。
3. `TransporterUtility.AllSendableItems` Postfix: 同じく輸送ポッド候補から除外。

1.7でHarmony MODを要求する既存MODが公開されている（コミュニティ報告。Ludeonの公式記述ではない）。Harmonyが起動時に使えない場合はログに診断を出し、上記3点だけが無効になる（契約・防衛・遠征は動作）。この縮退も実機確認対象。

### 4.2 その他の主要シンボル

- 派閥: `Faction.GoodwillWith`, `Faction.TryAffectGoodwillWith(Faction, int, bool, bool, HistoryEventDef, GlobalTargetInfo?)`, `Faction.HostileTo`, `Faction.defeated`, `FactionManager.AllFactionsListForReading`。
- 襲撃: `StorytellerUtility.DefaultThreatPointsNow(IIncidentTarget)`, `PawnGroupMakerUtility.GeneratePawns(PawnGroupMakerParms, bool)`, `LordMaker.MakeNewLord(Faction, LordJob, Map, IEnumerable<Pawn>)`、`ThingDef.stealable`（バニラ盗難AIから封印箱を外す）。
- 施設: `Building.DeconstructibleBy(Faction)`（virtual、収納中の解体禁止）、`Building_Storage`。
- 時間: 1日=60,000ticks（`GenDate.TicksPerDay`をゲーム側で参照し、Coreは同値の定数を持つ）。

最終的な利用シンボルは`Source/RentalWarehouse`のコンパイル成功で照合する。コンパイル成功はシグネチャの一致のみを示し、ゲーム内の挙動を保証しない。

## 5. 実DLL（1.7.9787）による確認

2026-10-23にユーザーから提供されたゲームの`Assembly-CSharp.dll`（1.7.9787.38423、メソッド本体あり）、`0Harmony.dll`（3.0.0.0-rc.3）、`Data/Core/Defs`で、前節まで「本体非公開のため未確認」としていた点を確認した。提供物はリポジトリ・CI・配布ZIPに含めず、ローカルの作業領域でのみ使用した。

| 項目 | 確認方法 | 結果 |
|---|---|---|
| 封印箱の資産額 | `StatWorker_MarketValue.GetValueUnfinalized`を読解 | 基本値をstatBasesに持つ物はcompの`GetStatOffset`/`GetStatFactor`が加算・乗算される。MarketValueはimmutable扱いでないため盗難後の値変化も反映される。Massも`StatWorker`でcompのオフセットが入る |
| 未受領残高の資産額 | `WealthWatcher`を読解 | `WealthTotal`はフィールド`wealthItems + wealthBuildings + wealthPawns`の和、アイテムは`MarketValue × stackCount`。`ForceRecount`後に`wealthItems`へ1回加算する方式で二重計上しない。**不具合を発見し修正:** `ForceRecount`はプレイ中以外（`allowDuringInit=false`）で再計算せず戻るため、その場合は加算しないよう条件を合わせた |
| Harmonyパッチ | 実ゲームDLLとHarmony 3.0を読み込んだプロセスで本MODの`PatchAll`相当を実行 | 5件すべて対象メソッドへ適用（`AllReachableColonyItems`、`AllSendableItems`、`TryAbandonViaInterface`、`MapParent.Abandon`、`ForceRecount`）。2.3.1参照でビルドしたDLLが3.0で動くことも確認 |
| コンパイル | `-p:RimWorldManagedPath=<提供DLL>`でMOD本体とゲーム内試験DLLをビルド | エラー0・警告0 |
| XML定義 | 新設の`tools/DefValidator`（ゲームの`DirectXmlToObject`と同じ規則で、フィールド名・`LoadAlias`・`Class`・`li`・enum・型名・Def参照を照合）で`Mod/Defs`を実クラスと`Data/Core/Defs`に照合 | **不具合を発見し修正:** フィルターの`<disallowedSpecialFilters>`は読み込み後に作り直されて消える。バニラと同じ`<specialFiltersToDisallow>`へ変更。修正後は全件合格。検査ツール自体はバニラCoreの全定義で誤検知0件 |
| マップ破棄の順序 | `Game.DeinitAndRemoveMap`を読解 | `Notify_MyMapAboutToBeRemoved`（台帳への書き戻し）→`MapDeiniter.Deinit`→一覧から除去→`MapComponent.MapRemoved`の順。破棄後のThingは`mapIndexOrState=-3`となり`Destroyed`ではないため、箱の索引を地図単位で消す処理（前回追加）が必要だったことを確認 |
| 放棄 | `SettlementAbandonUtility`と`Settlement.Abandon`を読解 | `TryAbandonViaInterface`→`settlement.Abandon(false)`→`base.Abandon`で、`MapParent.Abandon`のPrefixが必ず通る |
| 敵の持ち去り | `Pawn.ExitMap`を読解 | 運搬中の物（Pawn以外）は退出時に`Destroy()`される。封印箱の破棄検知で紛失として精算される |
| 配送 | `DropPodUtility.DropThingsNear`を読解 | DLC判定なし |
| 盗難AI | `StealAIUtility`を読解 | `ThingDef.stealable=false`の物を候補から除外する |
| サイト地図生成 | `GetOrGenerateMapUtility.GetOrGenerateMap`を読解 | `mapParent.MapGeneratorDef`と`ExtraGenStepDefs`を使う。`MapParent.TickInterval`が`CheckRemoveMapNow`を呼ぶ |
| 到着確認 | `CaravanArrivalActionUtility.GetFloatMenuOptions`を読解 | `confirmActionProxy`が指定されると選択時にそれを経由する |
| 途中導入 | `World.ExposeComponents`/`FillComponents`を読解 | ロード時に不足しているWorldComponentを生成し、その後`FinalizeInit`が呼ばれる |
| 保存の時点 | `Autosaver`を読解 | 自動保存は`LongEventHandler.QueueLongEvent`でtick外に実行される。1tick内の処理（受注・精算・襲撃開始と記録）は保存に分断されない |
| 言語フォルダ | `LoadedLanguage`を読解 | `Japanese (日本語)`の旧名`Japanese`でもMODの訳が読まれる |

## 6. 未確認事項（実機が必要）

ゲームの起動・描画・実際のセーブ/ロードは引き続き実行できない（提供物に実行ファイルとエンジンのネイティブ部分が含まれないため）。

- 画面上の表示（1280x720/2560x1440）とテクスチャの見え方。
- AI（盗人・守備・増援）が実マップで意図どおり動くこと、バランス。
- 実際のセーブ/ロードを跨いだ状態の復元（Coreの往復テストとローダ規則の確認までは済み）。
