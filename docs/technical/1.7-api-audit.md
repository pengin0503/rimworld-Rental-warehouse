# RimWorld 1.7 API監査（T0）

2026-10-23。対象ビルドの参照アセンブリを読み取り、仕様10の技術ゲートA00の4条件に接続先を割り当てた記録。ゲーム本体のコードは転載していない（参照アセンブリにはメソッド本体が含まれない）。

## 1. 対象ビルドと参照

| 項目 | 固定値 | 根拠 |
|---|---|---|
| ゲーム | RimWorld 1.7.4985（Steam unstableブランチ） | NuGet `Krafs.Rimworld.Ref` 1.7.4985-unstable（2026-10-22公開、Ludeon許諾のメタデータのみの参照アセンブリ） |

| テスト | xUnit、`net10.0` | 計画の初期案net8.0から変更（同一SDKで揃えるため） |

ローカルにゲームがある場合は `-p:RimWorldManagedPath=<RimWorldの管理DLLフォルダ>` で実DLLを参照に切り替える。参照先は個人環境の値でありリポジトリに固定しない。ゲームDLL・参照パッケージはリポジトリ・配布ZIPに含めない。

1.7は2026-10-23時点でunstableブランチのみ。安定版公開時はビルド番号を更新し、本監査とA00～A16を再実施する。1.6は`net472`・Unityであり、本DLLは読み込めない。1.6対応は別ビルドが必要（仕様U5の拡張扱い）。

## 3. 設計変更: サイトマップの寿命

バニラの`MapParent`は自派閥Pawnがいなくなるとマップを破棄する。破棄させない場合マップは常時tickされ、仕様9「未ロードサイトのマップを常時起動しない」に反する。そこで次の方式とする（仕様7を更新）。

- 退出後のマップは破棄してよい。ただし破棄直前（`Notify_MyMapAboutToBeRemoved`）に、箱の所在（金庫内/地面/持出済）、金庫ごとの開錠進捗・破壊状態・損失判定済み、生存守備兵の残ポイント、警報・増援状態を`SiteRecord`へ書き戻す。
- 再訪時は`SiteRecord`から同じseed・同じ配置で再構築し、取得済みの箱・死亡した守備兵・破壊された金庫は戻さない。在庫・守備を無料補充しない。
- 撤収期限・警報は絶対tickで台帳側を進め、未ロード中に越えた増援は次のロードで一度だけ反映する。

仕様の禁止事項「在庫・死亡・損失状態を復元せず毎回新規マップで無料補充」には該当しない。

## 4. 補助的な接続先

### 4.1 Harmonyの必要性

最小限に限定し、次の3か所だけに使う。

1. `WealthWatcher.ForceRecount` Postfix: 未受領残高（地図上の実体がない）を資産額に加える。ThingComp方式では表現できない。
2. `CaravanFormingUtility.AllReachableColonyItems` Postfix: 自コロニー契約箱をキャラバン候補から除外。
3. `TransporterUtility.AllSendableItems` Postfix: 同じく輸送ポッド候補から除外。

1.7でHarmony MODを要求する既存MODが公開されている（コミュニティ報告。Ludeonの公式記述ではない）。Harmonyが起動時に使えない場合はログに診断を出し、上記3点だけが無効になる（契約・防衛・遠征は動作）。この縮退も実機確認対象。

### 4.2 その他の主要シンボル

- 派閥: `Faction.GoodwillWith`, `Faction.TryAffectGoodwillWith(Faction, int, bool, bool, HistoryEventDef, GlobalTargetInfo?)`, `Faction.HostileTo`, `Faction.defeated`, `FactionManager.AllFactionsListForReading`。
- 襲撃: `StorytellerUtility.DefaultThreatPointsNow(IIncidentTarget)`, `PawnGroupMakerUtility.GeneratePawns(PawnGroupMakerParms, bool)`, `LordMaker.MakeNewLord(Faction, LordJob, Map, IEnumerable<Pawn>)`、`ThingDef.stealable`（バニラ盗難AIから封印箱を外す）。
- 施設: `Building.DeconstructibleBy(Faction)`（virtual、収納中の解体禁止）、`Building_Storage`。
- 時間: 1日=60,000ticks（`GenDate.TicksPerDay`をゲーム側で参照し、Coreは同値の定数を持つ）。

最終的な利用シンボルは`Source/RentalWarehouse`のコンパイル成功で照合する。コンパイル成功はシグネチャの一致のみを示し、ゲーム内の挙動を保証しない。

## 5. 未確認事項（実機が必要）

本コンテナにRimWorld本体はなく、ゲームの起動・セーブ・描画は実行できない。以下はA00の「実機部分」として環境不足のまま残る。

- 統計計算でThingCompのstat係数がMarketValueへ反映されること、資産再計算への反映間隔。
- Harmony MODが1.7.4985で読み込まれ、上記Postfixが適用されること。
- 1.7のセーブ時点（tick中に保存が割り込まないこと）。
- テクスチャ（PNG）とXML Defが1.6と同じ形式で読み込まれること。
